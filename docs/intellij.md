# IntelliJ IDEA plugin

The plugin supports IntelliJ IDEA Community and Ultimate 2024.2 and newer.

Build it with `./gradlew :axl-intellij:buildPlugin` and install
`axl-intellij/build/distributions/axl-intellij-<version>.zip` with
*Settings | Plugins | Install Plugin from Disk*.

## Features

| Area | What works |
|------|------------|
| Editing | File type and icon, highlighting with a color settings page (annotations such as `@Test` in the metadata color, type parameters in a color of their own; `break` and `continue` are keywords, also after `->` in a `when` statement (`2 -> continue`, `else -> n += x`, where an assignment stands without braces too), and so is `use` before `(val`, a name elsewhere), brace matching, `//` and `/* */` commenting, folding of blocks, lambdas, comments and imports, structure view (an enum lists its fields and constants, a data class its fields and the methods of its body). *Reformat Code* runs the formatter of `axl fmt` on the whole file (also for a selection); the code style settings do not apply. |
| Errors | Syntax errors from the PSI parser and the translator's rules (shadowing, `try` placement, `$` in names, ...) while typing. The translation reads the declarations of the other `.axl` files of the file's source roots, for a test file also of the production roots of the modules it depends on, so a class implementing an interface of another file or a `when` over a sealed type of another file is checked as the build checks it. The translation also reads the classes of the module's classpath from the IDE's Java model (library jars, the Java sources of the module and of the modules it depends on, and the module's JDK), so a `when` over a sealed type or an enum of a library, a class implementing a generic interface of a library and a list passed where a library method takes an array or varargs are checked and translated as by `axl check`; while the IDE indexes, only the JDK is read. javac, Error Prone and NullAway errors of the module after a save: in Community through `axl check` from the bundled tools, in Ultimate through the language server. Both get the source roots and classpath of the IntelliJ modules; the language server is restarted when they change. |
| Quick fixes | `return try e` to `return e`; `try` inside an expression to a separate `val`; `import a.B.f` to `import fn a.B.f`. |
| Navigation | Completion of names, keywords and members of Java and Axolotl types, also where an `is` test narrows a value, and after `@` of the annotation types among the imports, the file's package and `java.lang`; go to declaration in `.axl` files and into Java, also from an annotation to its type; find usages and rename of functions, values, types, properties, methods, data class fields and enum constants, including Java callers and `import fn` lines. Interfaces list their values and the methods they require (`fn add(text: String) -> Int`) in the structure view and completion, and the methods navigate, rename and are found like those of classes. `x ?: throw Y` has the type of `x` for completion. Type parameters (`data class Pair<A, B>`, `fn largest<T : Comparable<T>>`) are declarations: a `T` inside the declaration resolves to it, is offered where a type is written, and is found and renamed within the declaration. `Pair<String, Int>("x", 1).first()` is a `String`, a call of a generic function or of a method of a generic type has the type its arguments tell, and a `T` value offers the members of its bound. `xs \|> first ?: fallback` parses as the fallback of the whole pipe. The fields of an enum (`enum Planet(val mass: Double)`) resolve, complete and rename on its constants (`Planet.EARTH.mass`); the methods of a data class body see the fields by name and navigate, rename and are found like those of a class; a class that extends a Java class (`class Worker : Thread("w")`) resolves and completes the members it inherits; the resource of `use (val reader = ...) { ... } else e -> ...` is a local of its block and `e` a parameter of its handler, an `Exception`. A property without a written type (`val items = ArrayList<String>()`, `var count = 0`) has the type of its value. `use`, `break`, `continue`, `print` and `readLine` are offered where a statement starts. |
| Java interop | Java code sees every `.axl` file as a class with its nested types, type parameters, constructors and members (completion, navigation, error highlighting) without a build: the file is translated in memory and exposed through `PsiElementFinder` and `PsiShortNamesCache`. The translation sees the other `.axl` files of the module, so a class implementing an interface of another file has the accessors of the interface's values, and `if (o is Some) o.value()` over an `Option<String>` of another file is `o instanceof Some<String>` in the Java view. Generic types and functions keep their type parameters and bounds, `Pair<A, B>` with `A first` and `static <T extends Comparable<T>> T largest(List<T> xs)`, so `new Pair<>("a", 1)` and `largest(List.of("a"))` have their types in Java. An enum with fields has the fields and their constructor, a class that extends a Java class extends it in the Java view too (`Loud extends Thread`), and a data class with a body is a record with those methods. The annotations of the generated Java are on the classes, methods, fields, record components and parameters, so Java sees `@Deprecated fn old()` as deprecated and JUnit finds `@Test` methods. The Java the build generates (`build/generated/axl`, `target/generated-sources/axl`) is excluded from the index. |
| Run | A run icon next to `fn main()` creates a Java application run configuration for the file's class. With the JUnit plugin, a class with `@Test` methods and each of them get a run icon too, which creates a JUnit run configuration of the generated class (`app.ParseTest`, or `app.Main$ParseTest` for a class in a file of another name) or of the one method. With Gradle or Maven delegation the build tool compiles the `.axl` sources first. |
| Debug | Line breakpoints in `.axl` files, stepping by `.axl` lines and `.axl` positions in frames, through the JSR-45 stratum `Axolotl`. The translator's locals (`$t1`, `$n1`, ...) are labeled "Axolotl internal" in the Variables view. |
| Tools | *Show Generated Java* (editor popup and Tools menu) opens the translation read-only in a split. The intention *Convert Java file to Axolotl* converts a class with static members and nested records, enums, interfaces and classes, or a single record, enum, interface or class, when each part has a one to one Axolotl form; an interface method with parameters or no result becomes `fn name(params) -> Type`, one without parameters that returns a value stays a `val`, and default, static and private methods are refused. Generic records, interfaces, classes and methods keep their type parameters, `class Box<T>` and `fn f<T>(...)`, with `T extends Comparable<T>` as `T : Comparable<T>`; several bounds or a wildcard in a bound are refused. Annotations stay on their declarations (nullness ones become `?`), `X.class` is written as it is with `Integer.class` as `Int.class`, and `List<?>` becomes `List<*>`. An enum whose one constructor sets its fields becomes `enum Planet(val mass: Double) { EARTH(5.97e24) }` (enums with methods are refused), a class that extends a Java class becomes `class Worker : Thread("w")` with the arguments of its `super(...)` call (a second constructor or other statements in it are refused), a record with methods a data class with a body, a `try` with one resource and one `catch` whose body is a call or a `throw` becomes `use (val r = ...) { ... } else e -> ...` (without a `catch`, with a `finally` or several catches it is refused), and `break` and `continue` stay as they are while labels are refused. |
| Import | Gradle projects with `org.axl.lang` get `src/*/axl` as source roots from the plugin's source sets; Maven projects with `axl-maven-plugin` get `src/main/axl` and `src/test/axl`. |

## How it is built

- Lexer: the compiler's ANTLR lexer behind an IntelliJ `Lexer`.
- Parser: a recursive descent parser on `PsiBuilder` for the same grammar, with error recovery.
- The other `.axl` files of the module are parsed with the compiler's parser and handed to the translator as
  siblings, each parsed again only when it changes.
- References resolve with the translator's scope rules; Java classes come from `JavaPsiFacade`.
- The command-line compiler and the language server are bundled in `server/lib` and run in their own
  JVM with the options Error Prone needs.

Debugging is checked by hand, see [the debugger check](intellij-debug-check.md).
